Documentación del Sistema de Diseño (TP FINAL)

a) Sobre el Caso - Biblioteca popular Mariano Moreno

Elegi la Asociación Cultural Mariano Moreno de Bernal (LA MORENO), fundada en agosto de 1932. Me parecio un buen caso porque es un lugar muy conocido en el barrio (esta en Belgrano 450) pero digitalmente estan no tan bien asique un sitio les viene re bien para que la gente los conozca y se asocie.

El Público: Aca asisten muchos pibes de Bernal y de Quilmes para el apoyo escolar y los talleres, pero tambien hay mucha gente grande (los adultos mayores) que van a buscar novelas y usar la sala de lectura. Por eso el sitio tiene que ser de facil de entendimiento, con letras grandes y colores tranquilos que no les cansen la vista.

Objetivos: El sitio sirve para informar los horarios, ver que talleres y actividades hay, explicar bien como hacerse socios y que la gente del barrio pueda colaborar, ya sea donando libros o sumandose como voluntarios para las clases de apoyo.

b) deconstruccion del sitio

Para armar este sitio tome como base lo que estuvimos viendo con las deconstrucciones visuales:

  • El sistema de Tarjetas (Cards): Copie la idea de encapsular informacion, como el titulo, descripcion y un boton en una sola tarjeta ("organismo") para que todo se mueva en bloque y no quede desparramado.
  • El tema de las Categorias: Las etiquetas de color (Socio Lector, gratuito, talleres) vienen de los colores de de YouTube, para que de un vistazo la gente sepa rapido de que se trata cada actividad.
  • Espaciados mas comodos: A diferencia de la interfaz mas apretada de youtube aca use espaciados mucho mas grandes pensando en la gente mayor para que no se les mezcle la informacion al leer.

c) Variables del Sistema (:root)

Deje todo configurado con Custom Properties en :root para poder cambiar cualquier cosa de diseño rapido sin tener que editar todos los estilosS:

d) Inventario de Componentes Atómicos

Arme todo pensando en los tres niveles dee Atomic Design. Nombres de clases en español para que sea mas facil:

  • Átomos (Atoms): .marca-logo, .enlace-nav, .btn-destacado, .btn-accion, .etiqueta-categoria, .texto-entrada.
  • Moléculas (Molecules): .tarjeta-servicio, .item-paso, .campo-contacto, .grupo-direccion, .formulario-consulta.
  • Organismos (Organisms): .encabezado-principal, .presentacion-hero, .seccion-problematica, .seccion-grilla, .pasos-involucrarse, .bloque-contacto, .pie-pagina.

e) Decisiones de Estructura

1. CSS Grid en serio: Para la estructura macro use Grid si o si, nada de flexbox para el layout grande (ese lo use para pavadas como alinear los botones o el menu). En desktop (1280px) lo configure en 12 columnas. El header, hero, problematica y footer ocupan todo el ancho de la grilla (de la columna 1 a la 13) y la parte de que hacemos se divide en 3 columnas iguales de 4 columnas cada una (span 4). En mobile es una sola columna vertical fluida.

2. El Container Query en la tarjeta de servicio: Para cambiar el formato de las tarjetas segun el espacio y no la pantalla, cree un contenedor de tarjeta y le meti container query. Cuando la celda es chica (menos de 500px), la tarjeta es vertical (imagen arriba, texto abajo). Si pasa los 500px, se convierte en horizontal (imagen a la izquierda y el texto al lado) sin tocar el viewport. Me parece clave para que la tarjeta se adapte sola este donde este.

.contenedor-tarjeta {
  container-type: inline-size;
  container-name: tarjeta;
}

@container tarjeta (min-width: 500px) {
  .tarjeta-servicio {
    flex-direction: row; /* Horizontal inteligente */
  }
}

3. Complicaciones y cosas mas dificiles: Lo que mas me costo fue hacer que calce todo perfecto en desktop (1280px) usando Grid sin romper la adaptabilidad y el comportamiento de las tarjetas. Al usar flexbox adentro de las tarjetas para empujar el boton al final, me pasaba que con textos de distintos largos se veia desparejo, pero lo pude solucionar usando flex-grow en el cuerpo de las tarjetas para que queden todas de la misma altura, pero con algunas guias y videos pude resolverslo de manera correcta.
